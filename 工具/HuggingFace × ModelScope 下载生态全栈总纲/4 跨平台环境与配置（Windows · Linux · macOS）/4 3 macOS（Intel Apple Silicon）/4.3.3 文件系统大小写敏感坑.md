> macOS 默认 APFS 是**大小写不敏感**（case-insensitive，CI）。HF 仓库里有些项目恰好出现同名异 case 的两个文件，下载到 macOS 会**互相覆盖**，最终只剩一个，加载报 `FileNotFoundError`。

## 自检

```bash
diskutil info / | grep -i "File System Personality"
# 输出：
#   File System Personality: APFS              ← 默认，case-insensitive
#   File System Personality: APFS (Case-sensitive) ← 已开 case-sensitive
```

或一行 Python：

```bash
python -c 'import os; open("X.txt","w").close(); print(os.path.exists("x.txt"))'
# True = 大小写不敏感（坑）
# False = 大小写敏感（安全）
```

## 典型受害仓库（不完全清单）

- 含 `README.md` 与 `Readme.md` 两个版本的旧 fork

- 子目录里有 `Tokens.json` 与 `tokens.json` 共存的数据集

- Stable Diffusion 一些 community 仓库里 `vae/` 与 `VAE/` 并存

## 处方一：建 Case-sensitive APFS Volume（推荐）

```bash
# 1. 打开磁盘工具，或命令行建
diskutil apfs addVolume disk1 "Case-sensitive APFS" HFCache
# 2. 挂在 /Volumes/HFCache，把 HF_HOME 指过去
export HF_HOME=/Volumes/HFCache/huggingface
export MODELSCOPE_CACHE=/Volumes/HFCache/modelscope
```

优势：与系统盘隔离，不影响 Time Machine、Spotlight；空间动态分配，不预占。

## 处方二：用磁盘工具 GUI 建

1. 打开「磁盘工具」

1. 选中 Container（不是物理盘）

1. 「+」 → 添加 APFS 宗卷 → 「格式」选 **APFS（区分大小写）**

1. 命名 `HFCache`

1. 在 zshrc 把 `HF_HOME` 指向 `/Volumes/HFCache/...`

## 处方三：建 disk image（妥协）

```bash
hdiutil create -size 200g -fs "Case-sensitive APFS" -volname HFCache ~/HFCache.dmg
hdiutil attach ~/HFCache.dmg
```

开机自动挂载需要写 LaunchAgent；不太优雅，仅当你不想动主盘时用。

## 千万别做

- ❌ **整盘格式化为 case-sensitive**：会导致一部分 macOS 软件（Adobe、Steam、Photoshop 旧版）拒绝运行。

## 已经下错怎么办

```bash
# 看 HF 缓存里是否有同名异 case 冲突
find ~/.cache/huggingface -type f | tr '[:upper:]' '[:lower:]' | sort | uniq -d
# 列出疑似冲突；逐一重新 huggingface-cli download <repo> --force-download
```

或者最简单：删掉对应 `models--*` 目录，把 HF_HOME 指到新建的 case-sensitive 卷，重新 `snapshot_download`。

## 与其它平台联动

如果你用 Time Machine / iCloud 同步开发盘，把 case-sensitive 卷**排除**出备份，避免和不敏感的备份盘来回拷出现 silent collision。
