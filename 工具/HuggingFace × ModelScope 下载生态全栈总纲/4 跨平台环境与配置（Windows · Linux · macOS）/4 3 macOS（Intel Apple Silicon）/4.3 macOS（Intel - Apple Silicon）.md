[[4.3.3 文件系统大小写敏感坑]]

> macOS 在 Intel 与 Apple Silicon（M1/M2/M3/M4）之间存在 **架构差异**：torch 的 MPS 后端、bitsandbytes 的不可用、Rosetta 2 翻译层都会影响下载与加载链路。另外，macOS 默认文件系统 **APFS 是大小写不敏感** 的，会让一部分 HF 仓库里的同名异 case 文件互相覆盖。

## 三大场景速览

- **环境变量**：`~/.zshrc` 适合交互式 shell；如果你想让 GUI 应用（VSCode、Cursor、PyCharm）也读到，需要 `launchctl setenv` 写入 user agent。

- **架构差异**：`uname -m` = `arm64` 即 Apple Silicon；某些预编译 wheel 仅 x86_64（如 bitsandbytes-foundation），需要 `arch -x86_64` + Rosetta 或换用 mlx-lm。

- **大小写**：`diskutil info /` 看 `File System Personality`。要彻底解决，新建一个 **Case-sensitive APFS Volume** 专门放 HF 缓存。
