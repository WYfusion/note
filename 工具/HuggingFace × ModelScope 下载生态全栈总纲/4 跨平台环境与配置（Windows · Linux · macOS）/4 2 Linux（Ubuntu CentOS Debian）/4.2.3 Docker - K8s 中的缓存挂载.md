> 容器化场景的核心矛盾：**镜像不该带模型**（太大、不可变），但**容器启动后要立刻能读到模型**。解法统一为：**把宿主机缓存目录挂进容器**。

## Docker：单机最佳实践

```bash
# 1. 在宿主机准备缓存目录
mkdir -p /data/hf-cache /data/ms-cache
# 2. 跑容器时挂载 + 注入变量
docker run --rm --gpus all \
  -v /data/hf-cache:/root/.cache/huggingface \
  -v /data/ms-cache:/root/.cache/modelscope \
  -e HF_ENDPOINT=https://hf-mirror.com \
  -e HF_HUB_ENABLE_HF_TRANSFER=1 \
  -e MODELSCOPE_DOMAIN=www.modelscope.cn \
  -e HF_TOKEN=$HF_TOKEN \
  pytorch/pytorch:2.4.0-cuda12.4-cudnn9-runtime \
  python -c "from huggingface_hub import snapshot_download; snapshot_download('Qwen/Qwen2.5-7B-Instruct')"
```

## Dockerfile 推荐写法

```docker
FROM pytorch/pytorch:2.4.0-cuda12.4-cudnn9-runtime

# 镜像/加速器变量写进镜像（避免每次 docker run 重复)
ENV HF_ENDPOINT=https://hf-mirror.com \
    HF_HUB_ENABLE_HF_TRANSFER=1 \
    HF_HOME=/cache/huggingface \
    MODELSCOPE_CACHE=/cache/modelscope \
    PYTHONUNBUFFERED=1

# 卷声明：提示用户挂载这里
VOLUME ["/cache/huggingface", "/cache/modelscope"]

RUN pip install --no-cache-dir 'huggingface_hub[hf_transfer]' modelscope
```

构建 + 跑：

```bash
docker build -t hf-runner .
docker run --rm --gpus all -v /data/hf-cache:/cache/huggingface hf-runner
```

## docker compose

```yaml
services:
  trainer:
    image: pytorch/pytorch:2.4.0-cuda12.4-cudnn9-runtime
    deploy:
      resources:
        reservations:
          devices: [{ driver: nvidia, count: all, capabilities: [gpu] }]
    environment:
      HF_ENDPOINT: https://hf-mirror.com
      HF_HUB_ENABLE_HF_TRANSFER: "1"
      HF_TOKEN: ${HF_TOKEN}
    volumes:
      - /data/hf-cache:/root/.cache/huggingface
      - /data/ms-cache:/root/.cache/modelscope
      - ./code:/workspace
```

## Kubernetes：PVC 共享缓存

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: hf-cache
spec:
  accessModes: ["ReadWriteMany"]      # 多 Pod 同时读
  resources:
    requests:
      storage: 1Ti
  storageClassName: nfs-csi
---
apiVersion: batch/v1
kind: Job
metadata:
  name: train
spec:
  template:
    spec:
      containers:
      - name: trainer
        image: pytorch/pytorch:2.4.0-cuda12.4-cudnn9-runtime
        env:
        - name: HF_ENDPOINT
          value: https://hf-mirror.com
        - name: HF_HOME
          value: /cache/huggingface
        - name: HF_TOKEN
          valueFrom:
            secretKeyRef:
              name: hf-secret
              key: token
        volumeMounts:
        - { name: hf-cache, mountPath: /cache/huggingface }
      volumes:
      - name: hf-cache
        persistentVolumeClaim:
          claimName: hf-cache
      restartPolicy: Never
```

## 离线镜像 build：把模型烤进去

极少数场景（如边缘部署、机房无外网），可以把模型预下载塞进镜像：

```docker
RUN pip install huggingface_hub && \
    huggingface-cli download Qwen/Qwen2.5-1.5B-Instruct --local-dir /opt/models/qwen --local-dir-use-symlinks False
ENV TRANSFORMERS_OFFLINE=1
```

> ⚠️ 把模型烤进镜像会让镜像膨胀到几十 GB；CI 镜像构建超时风险大。除非真的离线，否则**强烈不推荐**。

## 常见坑

- 容器里 `~/.cache/huggingface` 不存在 → 没挂载，每次重启都重下。

- `--gpus all` 没加 → torch 看不到 GPU，[model.to](http://model.to)("cuda") 报错。

- 多个 Pod 抢同一份 PVC → `RWX` 不是所有 StorageClass 都支持。AWS EFS / Azure Files / 本地 NFS 才可以。
