> 实验室 / 公司服务器上常见场景：**多人共享一份 HF / MS 缓存**，节省磁盘 + 加快首次加载。核心是 **POSIX 组 + setgid 位 + umask**。

## 目标结构

```jsx
/data/hf-cache/                  # 共享根目录
├── hub/                          # HF 仓库快照
├── datasets/                     # HF datasets
└── modules/                      # transformers 自定义代码

/data/ms-cache/                   # ModelScope 缓存
├── hub/
└── datasets/
```

## 一步到位的配置

```bash
# 1. 建组
sudo groupadd -r hfteam
# 2. 把目标用户加进组
sudo usermod -aG hfteam alice
sudo usermod -aG hfteam bob
# 3. 建目录并设置归属
sudo mkdir -p /data/hf-cache /data/ms-cache
sudo chgrp -R hfteam /data/hf-cache /data/ms-cache
# 4. 关键：setgid，让新文件继承组
sudo chmod -R 2775 /data/hf-cache /data/ms-cache
# 5. 每个组员设 umask
echo 'umask 002' >> /etc/profile.d/hfteam.sh
```

**setgid（数字 2 开头的 mode）**让任何用户在该目录下创建的文件都自动归属 `hfteam` 组，而不是创建者主组。

**umask 002** 让新建文件的默认权限是 `664` / `775`，保证同组可写。

## 每个用户的 ~/.bashrc

```bash
export HF_HOME=/data/hf-cache
export MODELSCOPE_CACHE=/data/ms-cache
```

## 共享 token 的安全做法

- ❌ 不要：所有人共用同一份 `~/.cache/huggingface/token`。

- ✅ 推荐：每人 `huggingface-cli login` 各自登录；token 文件权限 `600`。下载产物仍写入共享目录，但请求各自鉴权。

## ACL：更精细的权限

```bash
# 给运维 ops 用户只读权限，又不加入 hfteam
sudo setfacl -R -m u:ops:rX /data/hf-cache
# 让新文件也继承这条 ACL
sudo setfacl -R -d -m u:ops:rX /data/hf-cache
# 查看
getfacl /data/hf-cache
```

## 常见坑

- **Alice 下载完，Bob 加载报 PermissionError**：Alice 的 umask 是 022，新文件 644，其他组员读不进。`umask 002` + setgid 才彻底。

- **某些子目录权限错乱**：HF 在写 `*.lock` 时偶尔创建普通文件而非走 setgid 的目录。一次性修：`sudo chgrp -R hfteam /data/hf-cache && sudo chmod -R g+rwX,o+rX /data/hf-cache`。

- **磁盘 quota**：如果文件系统启用了 user quota，共享缓存会算到最先下载那个人的额度上。可改用 group quota：`edquota -g hfteam`。

- **NFS 上的 symlink**：NFSv3 行为正常；某些 SMB / CIFS 挂载不支持 symlink，HF 会回退到拷贝，磁盘占用翻倍。
