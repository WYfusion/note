> WSL2 是 Windows 上跑 HF / ModelScope 工具链的「准 Linux 体验」首选。但它不是免费午餐：**文件 I/O 跨边界会慢 10×**，环境变量也不通。

## 三大铁律

### 1. 缓存目录放在 WSL 文件系统内，而不是 `/mnt/c`

- ✅ 正确：`HF_HOME=/home/<user>/.cache/huggingface`（这是 ext4 上）

- ❌ 错误：`HF_HOME=/mnt/c/Users/<user>/.cache/huggingface`（每次读 9P 协议跨 VM 边界，慢且 symlink 行为奇怪）

性能差距：在 `/mnt/c` 上 `huggingface-cli scan-cache` 一个 7B 模型可能耗 30 秒；放在 `~/.cache` 上只要 1–2 秒。

### 2. 环境变量在 Linux 一侧单独设

WSL **不继承** Windows 用户变量。把 `export HF_ENDPOINT=...` 写到 `~/.bashrc`：

```bash
echo 'export HF_ENDPOINT=https://hf-mirror.com' >> ~/.bashrc
echo 'export HF_HUB_ENABLE_HF_TRANSFER=1' >> ~/.bashrc
echo 'export HF_HOME=$HOME/.cache/huggingface' >> ~/.bashrc
source ~/.bashrc
```

### 3. GPU passthrough

```bash
nvidia-smi  # 必须能看到 GPU
python -c "import torch; print(torch.cuda.is_available())"
```

如果 `nvidia-smi` 报错，去 Windows 装 **NVIDIA Driver for WSL2**（不是 Linux 驱动！），然后 `wsl --shutdown` 重启。

## 与 Windows 主机互通

### 从 WSL 访问 Windows 文件

```bash
ls /mnt/c/Users/<you>/Downloads
```

### 从 Windows 访问 WSL 文件

```jsx
\\wsl$\Ubuntu\home\<you>\.cache\huggingface
```

资源管理器地址栏直接粘贴。**别在 Windows 这边 cut/paste WSL 文件**，可能丢权限位。

### 镜像挂载到 Windows

```bash
# 把 WSL 的下载目录链给 Windows（在 PowerShell 里执行）
New-Item -ItemType SymbolicLink -Path "D:\hf-wsl" -Target "\\wsl$\Ubuntu\home\<you>\.cache\huggingface"
```

## 性能调优

```
# %UserProfile%\.wslconfig（注意是用户家目录，不是 Linux 内）
[wsl2]
memory=24GB
processors=8
swap=8GB
localhostForwarding=true
```

改完 `wsl --shutdown` 才生效。

## 常见错误对照

|现象|原因|处方|
|---|---|---|
|下载极慢，CPU 100%|缓存目录在 /mnt/c|挪到 ~/.cache|
|VSCode Remote 连接断开|WSL 内存吃满 OOMKill|.wslconfig 加 memory|
|[torch.cuda.is](http://torch.cuda.is)_available() False|没装 WSL 用 NVIDIA 驱动|Windows 侧安装专版驱动|
|symlink 警告|WSL 内的 ext4 已经支持，无害|HF_HUB_DISABLE_SYMLINKS_WARNING=1|
