> 这是 Windows 用户在下载 HF 大模型时最容易栽跟头的两类问题：**MAX_PATH=260** 与 **Git LFS / hf_hub 软链接缓存**。

## 长路径（MAX_PATH=260）

### 症状

- 下载到一半报 `[Errno 22] Invalid argument` 或 `The system cannot find the path specified`。

- 路径形如 `C:\Users\you\.cache\huggingface\hub\models--meta-llama--Llama-3.1-405B-Instruct\blobs\<40位hash>` 已经接近 260。

- 一旦再加一层子目录、长 hash、长 sharded 文件名，必然爆。

### 三道处方

1. **注册表启用长路径**（最根本）：

```powershell
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name 'LongPathsEnabled' -Value 1 -PropertyType DWORD -Force
```

重启后所有调用 Win32 API 的程序都能用 32K 路径。

1. **把 HF_HOME 挪到短路径**：

```powershell
[Environment]::SetEnvironmentVariable("HF_HOME", "D:\hf", "User")
```

1. **应用程序清单**：自己写的 Python 打包成 exe 时，需要 `app.manifest` 里 `<longPathAware>true</longPathAware>` 才真正享受到长路径。

## Git LFS / hf_hub 软链接

### 缓存结构（HF）

```jsx
hub/
├── models--owner--repo/
│   ├── blobs/<hash>            # 真实文件（大）
│   ├── refs/<branch>           # 指向 commit
│   └── snapshots/<commit>/     # 符号链接指向 blobs/<hash>
```

**snapshots 下是 symlink**，而不是真实文件。这能让多个版本共享同一份权重，节省磁盘。

### Windows 上的坑

- 默认账户**没有 SeCreateSymbolicLinkPrivilege**。下载时 hf_hub 会回退到「拷贝」模式，导致 **磁盘占用翻倍**，并打印警告：`UserWarning: cache-system uses symlinks by default to efficiently store duplicated files`。

- 解决方案二选一：
    
    - **方案 A**：启用「开发者模式」（`Settings → Privacy & security → For developers`），symlink 不再需要管理员。
    
    - **方案 B**：以管理员身份跑下载命令。
    
    - **方案 C（妥协）**：接受拷贝，但显式设置 `HF_HUB_DISABLE_SYMLINKS_WARNING=1` 屏蔽噪音。
    

### 验证 symlink 是否生效

```powershell
Get-ChildItem -Force "$env:HF_HOME\hub\models--meta-llama--Llama-3.1-8B\snapshots\<commit>" | Where-Object Mode -match 'l'
```

带 `l` 的行才是真 symlink。如果全是普通文件，说明回退到了拷贝。

## 综合检查清单

- [ ] LongPathsEnabled = 1（注册表）

- [ ] 开发者模式 = ON（系统设置）

- [ ] HF_HOME 指向非 C 盘短路径，且**无中文、无空格**

- [ ] OneDrive 已把 HF_HOME 排除

- [ ] 磁盘格式是 NTFS（FAT32/exFAT 不支持 symlink）
