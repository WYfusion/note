## 0. 定位

> 一句话：本页是「先踩过一遇点」的集中营。后面各 L3/L4 会重复提及部分坑，但本页集中给出「误区 → 为什么错 → 怎么取」三件套。

## 1. 误区一：「仓库路径 = 本地路径」

调用 `snapshot_download(repo_id=...)` 后拿到的**不是**一个清爽的 `./Qwen2.5-0.5B-Instruct/` 目录，而是位于 `~/.cache/huggingface/hub/models--Qwen--Qwen2.5-0.5B-Instruct/snapshots/<commit>/` 的**软链接森林**。

> [!important]
> 
> **误区**：拿到路径后 `rsync -a` 拷到别的机器上。→ 会拷贝**空软链接**，透不过实际的 blobs/。
> 
> **正确做法**：
> 
> - 能控制代码时，传 `local_dir=...` 使用**真文件**（默认 `local_dir_use_symlinks=False`）。
> 
> - 拷贝时加 `-L`（`rsync -aL`）或 `cp -L`，跳软链接拿实体。

## 2. 误区二：「HF_ENDPOINT 设了就万事大吉」

`HF_ENDPOINT=https://hf-mirror.com` 只接管了 `huggingface_hub` SDK 发出的请求。以下**不被接管**：

|调用点|是否同享镜像|原因|
|---|---|---|
|`huggingface_hub.snapshot_download`|✅|走 SDK|
|`AutoModel.from_pretrained(...)` (transformers)|✅|底层调 SDK|
|`git clone https://huggingface.co/...`|❌|git 不读 env|
|`pip install transformers` 出去拉权重的脱锄脚本|❌|部分老脱锄脚本硬编码了 [huggingface.co](http://huggingface.co)|
|`hf_xet` 走的 Xet CAS 端点|仅部分镜像支持|镜像站未一定镜像 Xet|

> [!important]
> 
> **保险做法**：同时设 `HF_ENDPOINT` + `HF_HUB_ENABLE_HF_TRANSFER=0`（镜像上多线程会 429）+ 临时 `HF_HUB_DISABLE_XET=1`（避免镜像未镜 Xet 报错）。

## 3. 误区三：「`HF_TOKEN` 随调随贴」

在 Jupyter/Notebook 里写 `os.environ["HF_TOKEN"] = "hf_xxx"`，保存后推到 GitHub → token 泄漏。严重时会变成 HF 官方邮件批量作废。

**正确做法**：

```bash
# 一次性交互登录，token 存在 ~/.cache/huggingface/token (0600 权限)
hf auth login

# 或在 .env / docker secret 中管理
export HF_TOKEN="$(cat /run/secrets/hf_token)"
```

## 4. 误区四：「文件下完就是完整的」

网络拖累下 `safetensors` 可能下一半负应「艰难财」。`huggingface_hub` 0.23+ 默认会校验 `etag`，但**不校全文件 sha256**。

**验证脚本**：

```python
# verify_safetensors.py —— 检查 safetensors 是否可被完整加载
import sys
from pathlib import Path
from safetensors import safe_open  # pip install safetensors

root = Path(sys.argv[1])
for f in root.rglob("*.safetensors"):
    try:
        with safe_open(f, framework="pt") as h:
            n_keys = len(list(h.keys()))
        print(f"✅ {f.name:40s} keys={n_keys}")
    except Exception as e:
        print(f"❌ {f.name:40s} 错误: {e}")
```

## 5. 误区五：「两个镜像缓存互通」

HF 和 MS 的缓存目录、哈希命名、软链结构**完全不同**，互拷一份不能让另一个识别。需要双缓存请**重新下一次**（或走 3.5 中的 `USE_HF=1` 抽象）。

## 6. 误区六：「hf_transfer 必提速」

`hf_transfer` 以 8 线程 Rust 传输增带宽，但：

- 在**镜像站**上可能被限速 / 429；

- 代理绿色通道下可能反而变慢；

- 不支持带鉴权的 Xet CAS 某些组合。

> [!important]
> 
> **经验值**：原生直连打开，镜像站关闭：
> 
> ```bash
> export HF_HUB_ENABLE_HF_TRANSFER=1   # 直连
> export HF_HUB_ENABLE_HF_TRANSFER=0   # 镜像 / 弱网
> ```

## 7. 总结清单

|场景|一句话避坊指南|
|---|---|
|跨机器拷贝缓存|`rsync -aL` 或用 `local_dir` 重拉|
|镜像不生效|三件套：`HF_ENDPOINT` • `HF_HUB_ENABLE_HF_TRANSFER=0` • `HF_HUB_DISABLE_XET=1`|
|token 泄漏|用 `hf auth login`，不要硬编码|
|文件不全|`safetensors` • sha256 双重验证|
|HF/MS 混用|重入 或 `USE_HF=1`|
|`hf_transfer` 报错|镜像下关掉，直连下开|
