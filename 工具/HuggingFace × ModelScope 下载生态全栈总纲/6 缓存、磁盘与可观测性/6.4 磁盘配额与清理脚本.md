## 查看体量

```bash
# HF 顶层
huggingface-cli scan-cache | awk 'NR>2 {print $3, $1}' | sort -hr | head -20

# MS 顶层
du -sh ~/.cache/modelscope/hub/*/* 2>/dev/null | sort -h | tail -20

# 总计
du -sh ~/.cache/huggingface ~/.cache/modelscope
# 剩余空间
df -h ~/.cache
```

## 一键清理脚本（bash）

```bash
#!/usr/bin/env bash
# cache-gc.sh——保留 main 与近 30 天访问过的 commit，其它全删
set -euo pipefail
DAYS=${DAYS:-30}

echo "== HF =="
python - <<PY
import time
from huggingface_hub import scan_cache_dir
now = time.time()
info = scan_cache_dir()
to_del = []
for repo in info.repos:
    for rev in repo.revisions:
        if "main" in rev.refs:
            continue
        if rev.last_accessed and now - rev.last_accessed.timestamp() < ${DAYS}*86400:
            continue
        to_del.append(rev.commit_hash)
if to_del:
    s = info.delete_revisions(*to_del)
    print("Will free:", s.expected_freed_size_str)
    s.execute()
else:
    print("Nothing to delete.")
PY

echo "== ModelScope =="
find ~/.cache/modelscope/hub -maxdepth 2 -mindepth 2 -type d -atime +${DAYS} -print -exec rm -rf {} +
```

跑：

```bash
DAYS=15 ./cache-gc.sh
```

## cron / systemd timer

```jsx
# crontab -e——每周日凌晨 3 点跑一轮
0 3 * * 0 /usr/local/bin/cache-gc.sh >> /var/log/hf-cache-gc.log 2>&1
```

systemd timer：

```
# /etc/systemd/system/cache-gc.service
[Unit]
Description=HF + MS cache GC
[Service]
Type=oneshot
ExecStart=/usr/local/bin/cache-gc.sh
Environment=DAYS=30

# /etc/systemd/system/cache-gc.timer
[Unit]
Description=Run cache-gc weekly
[Timer]
OnCalendar=Sun 03:00
Persistent=true
[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable --now cache-gc.timer
```

## 磁盘配额与警报

### Linux quota（多用户场景）

```bash
# 为 hfteam 组设 500GB 硬限 + 450GB 软限
sudo edquota -g hfteam
```

### 阈值警报脚本

```bash
#!/usr/bin/env bash
THRESHOLD=85           # %
USE=$(df --output=pcent ~/.cache | tail -1 | tr -dc '0-9')
if (( USE > THRESHOLD )); then
  echo "[ALERT] cache disk at ${USE}%" | mail -s "HF cache disk usage" you@example.com
fi
```

配到 cron 每小时跑一次。

## 安全清理原则

1. **不要在下载进行中清理**：`flock` 会被占。

1. **保留一个 base + 最新**：避免隐含依赖重拉。

1. **同时清 HF 和 MS 时错开**：资源 IO 不争抢。

1. **先 dry-run 再执行**：HF API 的 `strategy.expected_freed_size_str` 中间务必先打印。

1. **MS 用 atime** 可能不准：如果文件系统挂载了 `noatime`，改用 `mtime`。

## 与云存储联动的备份策略

- 本地仅保 30 天，过期拼拽 S3 / OSS。

- 备份含 commit sha 的压缩包，以 `repo@<commit>.tar.zst` 升名。

- 恭复时 untar 到 `$HF_HOME/hub/models--...` 后走 `from_pretrained` 能被识别，需顺指向 refs/<branch> 文件补上 commit sha。
