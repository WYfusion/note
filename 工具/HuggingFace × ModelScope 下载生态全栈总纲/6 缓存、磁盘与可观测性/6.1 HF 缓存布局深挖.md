> HF 的本地缓存 = 以 `HF_HOME` 为根的一棵**三层 CAS 树**（content-addressable storage）。它不是简单的 `git clone` 镜像目录，读懂它能避免 90% 的「明明下过为什么加载不到」问题。

## 默认路径

|平台|默认 HF_HOME|
|---|---|
|Linux|~/.cache/huggingface|
|macOS|~/.cache/huggingface（也可用 ~/Library/Caches/huggingface）|
|Windows|%USERPROFILE%.cachehuggingface|

## 完整布局

```jsx
$HF_HOME/
├── hub/                            # 模型 + tokenizers + Spaces 的 git 缓存宇宙
│   ├── models--<owner>--<repo>/
│   │   ├── blobs/                  # 真实文件，hash 命名
│   │   │   ├── abcd1234...   # config.json
│   │   │   └── ef567890...   # model.safetensors
│   │   ├── refs/                   # 分支 → commit 映射
│   │   │   └── main           # 内容是 commit sha
│   │   └── snapshots/<commit>/     # 软链接贴面，指向 blobs/<hash>
│   │       ├── config.json -> ../../blobs/abcd1234
│   │       └── model.safetensors -> ../../blobs/ef567890
│   ├── datasets--<owner>--<repo>/    # 同上，但在 hf-mirror.com/datasets
│   └── spaces--<owner>--<repo>/
├── datasets/                       # datasets 库生成的 arrow 缓存
│   └── <fingerprint>.arrow
├── modules/                        # transformers 动态加载的自定义代码
└── token                           # 登录 token，权限 600
```

## 为什么是 CAS 者 blobs + snapshots

- **去重**：Qwen2.5-7B-Instruct main 与某个旧 commit 如果几个大文件一样，blobs/ 里只存一份。

- **原子切换**：snapshots/<commit> 只要存在且软链完整，”这个 commit 可用”就成立。

- **断点续传**：下一半的文件会以 `<hash>.incomplete` 在 blobs/ 里亮相，重跑同 repo 会接上。

## 本地路径 ↔ repo_id 映射

```python
from huggingface_hub import snapshot_download
local_path = snapshot_download("Qwen/Qwen2.5-7B-Instruct")
print(local_path)
# /Users/you/.cache/huggingface/hub/models--Qwen--Qwen2.5-7B-Instruct/snapshots/<commit>
```

`from_pretrained("Qwen/Qwen2.5-7B-Instruct")` 底层等价于 `from_pretrained(local_path)`。

## refs/ 是干吗用的

```bash
cat ~/.cache/huggingface/hub/models--Qwen--Qwen2.5-7B-Instruct/refs/main
# 84a8d99e5ab8e3c4...
```

refs/main 里存的 commit sha = snapshots/ 下哪个目录可用。远端发生更新时，新 commit 会被拉下来，新建 snapshots/<new>，改写 refs/main；旧 snapshots/<old> 仍在，可以主动 GC。

## TRANSFORMERS_OFFLINE 与缓存的交互

- `TRANSFORMERS_OFFLINE=1`：from_pretrained 不会发 HTTP，**只查 hub/**。拉不到 commit 就报 `OSError: Can't load`。适合 CI / 生产环境冻结版本。

- `HF_HUB_OFFLINE=1`：huggingface_hub 本身同样完全不发请求。

## 与下载器选型

- `**huggingface-cli download**` **/** `**snapshot_download**` **/** `**from_pretrained**` 都写进 hub/，互为可用。

- `**hfd**` **/** `**aria2c**` **手拉**：产物是「纯文件目录」，不是 hf_hub 格式。`from_pretrained` 可以直接读路径，但**不会被包在 hub/ 里**，`scan-cache` 也不计入。

## Xet 存储

HF 正在迁移到 Xet（锁块去重、底层 chunk 粒度高于 blob）。上层布局不变，但 `blobs/<hash>` 本身可能是一个 Xet 载入指针。对用户**透明**，但在多仓库共享权重时能提供额外去重收益。

## 本地检查命令集

```bash
# 列出所有本地仓库与体量
huggingface-cli scan-cache
# 顶层目录 du
du -sh ~/.cache/huggingface/hub/models--*/ | sort -h
# 查看某 repo 的全部 commit
ls ~/.cache/huggingface/hub/models--Qwen--Qwen2.5-7B-Instruct/snapshots/
# 查看一个文件是不是 symlink
file ~/.cache/huggingface/hub/models--Qwen--Qwen2.5-7B-Instruct/snapshots/*/model.safetensors
```
