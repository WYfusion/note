## 0. 定位

> 一句话：本页讲透 HF 下载的三种“加速变助”：**hf_xet（块去重）**、**hf_transfer（多线程传输）**、**hfd（社区脚本，aria2/wget 多线程）**。

## 1. 三者机制对比

|加速器|机制|出处|取代什么|何时启用|
|---|---|---|---|---|
|**hf_xet**|Content-Addressable Storage 块去重|HF 官方 (Rust)|Git LFS|启用 Xet 存储后端的仓库，默认自动|
|**hf_transfer**|多线程 HTTP、Rust 零拷贝|HF 官方 (Rust)|默认 requests 单线程|带宽充足 · 直连 HF|
|**hfd**|shell 脚本，调 aria2c 或 wget 多连接|社区 (hf-mirror)|SDK 下载|镜像站 · 100GB+ 全量拉|

## 2. 带宽利用率的数学直观

单线程 TCP 吞吐受限于 BDP（Bandwidth-Delay Product）：

$$\text{Throughput}_{\max} = \frac{\text{Window}}{\text{RTT}}$$

跨国 RTT 常 ≋ 150,text{ms}$，即使 Window = 4MB 也仅 ≋ 213,text{Mbps}$。多线程把多个独立 TCP 连接叠加：

$$\text{Throughput}_{N} \approx N \cdot \frac{\text{Window}}{\text{RTT}} \quad (N \le \text{服务器并发限})$$

这是 `hf_transfer`、`hfd -x 8` 能轻松跡进 10× 的原因。但到达服务器并发限/CDN 限速后边际收益迫近 0。

## 3. 三种加速器启用示例

```bash
# (1) hf_xet —— 启用 Xet 后端仓库会自动走
export HF_HUB_DISABLE_XET=0
pip install -U "huggingface_hub[hf_xet]"

# (2) hf_transfer
export HF_HUB_ENABLE_HF_TRANSFER=1
pip install -U hf_transfer
hf download Qwen/Qwen2.5-7B --local-dir ./qwen7b

# (3) hfd 脚本 (玩镜像场景)
bash <(curl -fsSL https://hf-mirror.com/hfd/hfd.sh) \
  Qwen/Qwen2.5-7B --tool aria2c -x 8 --local-dir ./qwen7b_aria2
```

## 4. 选型决策

> [!important]
> 
> **工程选型链**：
> 
> - 仓库原生 Xet 后端 → 什么也别动，`**hf_xet**` **默认已是最佳**。
> 
> - 仓库还是 LFS，在海外 → `hf_transfer=1`。
> 
> - 仓库还是 LFS，在国内 → 镜像 + `hfd -x 8`，**关** `**hf_transfer**`。
