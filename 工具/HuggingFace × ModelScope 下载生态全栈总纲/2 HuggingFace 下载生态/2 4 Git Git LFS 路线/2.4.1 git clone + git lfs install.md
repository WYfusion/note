## 0. 定位

> 一句话：`git lfs clone` 是「低级」、可复现、能 push 的渠道。但能 push 不代表你该用 ——训练场景下几乎总是比 `snapshot_download` 慢且费磁盘。

## 1. 最小可跑路径

```bash
# 1) 装 git lfs。不仅然 .safetensors / .bin 会被当文本拉下指针。
sudo apt-get install -y git-lfs   # Linux
brew install git-lfs               # macOS
winget install GitHub.GitLFS       # Windows
git lfs install                    # 全局启用 (只执行一次即可)

# 2) 克隆 (HTTPS、弱鉴权 = 公开 repo、强鉴权 = 需 PAT)
GIT_LFS_SKIP_SMUDGE=0 git clone https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct

# 3) 查看
ls -lh Qwen2.5-0.5B-Instruct/
```

## 2. 「跳 LFS 拉」与后推拉取

```bash
# 仅拉指针文件，不拉实质 LFS
GIT_LFS_SKIP_SMUDGE=1 git clone https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct

cd Qwen2.5-0.5B-Instruct
head -c 200 model.safetensors
# version https://git-lfs.github.com/spec/v1
# oid sha256:xxxxxxxx
# size 988097824

# 重拉指定文件
git lfs pull --include "*.safetensors"
git lfs pull --include "tokenizer*,*.json"
```

## 3. 鉴权与 PAT

```bash
# HTTPS 拉 private repo、需在 git credential helper 里存入 token
hf auth login --token $HF_TOKEN --add-to-git-credential

# 或手动写
printf "protocol=https\nhost=huggingface.co\nusername=USER\npassword=$HF_TOKEN\n" \
    | git credential approve

# SSH 克隆 (需在网页设置上传公钥)
git clone git@hf.co:Qwen/Qwen2.5-0.5B-Instruct
```

## 4. push 权重的全流程

```bash
# 创建本地项目
mkdir my-model && cd my-model
git init
git lfs install

# 关联远端
git remote add origin https://huggingface.co/my-org/my-model

# 告诉 lfs 哪些模式跳 LFS
git lfs track "*.safetensors" "*.bin" "*.gguf"
git add .gitattributes

# 贴权重
cp /path/to/your/model.safetensors .
git add model.safetensors
git commit -m "add weights v0.1"

# push (需在 git credential 里有 HF token)
git push origin main
```

## 5. 与 `snapshot_download` 的对比

|场景|git lfs clone|snapshot_download|
|---|---|---|
|完全可复现|✅ .git 保留 commit|✅ revision 锾锁|
|仅拉部分文件|需 SKIP_SMUDGE + lfs pull|原生 `allow_patterns`|
|磁盘占用|2x (objects + working tree)|1x|
|能 push|✅|❌ (需如下推 `hf upload`)|
|仅训练|不推荐|首选|

## 6. 踩过的坊

> [!important]
> 
> **1) 仓库被占 50GB**—— `.git/lfs/objects/` + `working tree` 会报拷一份。`git lfs prune` 调后可清历史。
> 
> **2) push 报** `**pre-receive hook declined**`—— 多是文件超过 5GB 限额、或 commit 过大。请拆往补交。
> 
> **3) Windows 上区分大小写路径问题**—— macOS / Windows 默认 case-insensitive，略胆金变名可能混业。记得 `git config core.ignorecase false`。
