> 大多数「下不动」问题都是网络层问题。本节提供一套「DNS → TCP/TLS → 代理 → HTTP」由表及里的排查顺序。

## 第 0 步：确定你在哪个 endpoint

```bash
echo "HF_ENDPOINT = ${HF_ENDPOINT:-<unset>}"
env | grep -E "(HTTP|HTTPS)_PROXY" || true
```

## 第 1 步：DNS

```bash
getent hosts huggingface.co
getent hosts hf-mirror.com
getent hosts www.modelscope.cn
# 或
nslookup huggingface.co 8.8.8.8
dig +short huggingface.co
```

问题与处方：

- **返回空 / NXDOMAIN**：内网 DNS 不观。临时 `echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf`。

- **返回错误 IP**（如 127.0.0.1）：DNS 污染。加 `/etc/hosts` 明示映射：

```jsx
# 从 https://hf-mirror.com 页面获取最新 IP
104.18.x.x  hf-mirror.com
```

## 第 2 步：TCP 可达

```bash
nc -vz hf-mirror.com 443
curl -v -o /dev/null https://hf-mirror.com/api/models/bert-base-uncased 2>&1 | head -30
```

看三项：`Trying ...` IP 是否合理、`Connected to ...` 是否出现、返回码。

## 第 3 步：TLS / SSL

```bash
openssl s_client -connect hf-mirror.com:443 -servername hf-mirror.com </dev/null 2>&1 | grep -E "(subject|issuer|Verify)"
```

问题与处方：

- `unable to get local issuer certificate`：公司代理拦 SSL。

```bash
export REQUESTS_CA_BUNDLE=/etc/ssl/certs/company-ca.pem
export SSL_CERT_FILE=$REQUESTS_CA_BUNDLE
export CURL_CA_BUNDLE=$REQUESTS_CA_BUNDLE
```

- `certificate has expired`：客户端时间偏差太大。`sudo ntpdate ntp.aliyun.com` 同步。

## 第 4 步：代理

```bash
env | grep -E "(HTTP|HTTPS|NO)_PROXY"
```

常见场景：

- 公司要求走代理：必须设 `HTTPS_PROXY=http://user:pass@proxy.corp:8080`；HF SDK 完全尊重。

- 本机启了 Clash / V2Ray 但未变量化：`export HTTPS_PROXY=http://127.0.0.1:7890`。

- 代理与镜像冲突：代理包住 [hf-mirror.com](http://hf-mirror.com) 的请求反而更慢。`export NO_PROXY=hf-mirror.com,.huggingface.co,modelscope.cn` 跳过。

## 第 5 步：HTTP 响应

```bash
curl -v https://hf-mirror.com/api/models/Qwen/Qwen2.5-7B-Instruct 2>&1 | tail -50
```

看返回码与 header：

- 200：正常

- 301/302：重定向，看 `Location:` 是否被内网迫转

- 401：可能需要 token

- 403：受控模型未插入 token

- 404：拼错 endpoint 或拼错 path（看是不是错将 `/blob/` 当作 `/resolve/`）

- 429：限流

- 5xx：服务端问题，重试

## 第 6 步：抲走路由

```bash
mtr -r hf-mirror.com
traceroute hf-mirror.com
```

判断是本机 / 出网 / 运营商 / 目标站哪一跳丢包。可与 [[8.2 SDK 层排查（版本 - token - endpoint）]] 对齐。

## 推荐脚本模板

```bash
#!/usr/bin/env bash
# diagnose.sh
for host in hf-mirror.com huggingface.co www.modelscope.cn; do
  echo "== $host =="
  getent hosts $host || echo "  DNS fail"
  nc -vz $host 443 2>&1 | head -2
  curl -sI -m 10 https://$host | head -1
  echo
done
```

## 场景化德

- **公众 WiFi 上学生**：会拦 https，走 `curl --resolve` 手推 IP。

- **以太网机房**：某些 IDC 出出被圻广告限流。使用企业云映射。

- **学校主机**：IPv6 默认优先但 hf-mirror IPv6 不是最佳。强制 IPv4：`export HF_HUB_DISABLE_IPV6=1`。
