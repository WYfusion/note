## 3.1.3.0 定位

> 一句话：VQ Collapse 是在训练中**「大量 code 从不被使用」**的现象，是 VQ 训练不稳的主要信号。FSQ 天生免疫。

---

## 3.1.3.1 什么是 collapse

设 codebook size $K = 1024$，训练后可能出现：

- 仅 30% 的 code 被使用。

- 某些 code 未在任何 batch 中被选中。

- 部分 code 被使用过多（1 个 code 占 20% 选择频率）。

造成「有效码表远小于 $K$」，表达能力限制。

## 3.1.3.2 collapse 御变过程


**本质**：arg-min 是「赢者通吝」，初期被选中的 code 被优化，未被选中的 code 永远不被训练。

## 3.1.3.3 诊断指标

|指标|公式|健康值|collapse 例|
|---|---|---|---|
|**Codebook usage**|$\frac{\#\{k: n_k > 0\}}{K}$|> 90%|< 30%|
|**Codebook perplexity**|$\exp(-\sum_k p_k \log p_k)$|~ K|远小于 K|
|**Top-1 frequency**|$\max_k p_k$|< 5%|> 20%|

## 3.1.3.4 VQ 上的缓解方法

> [!important]
> 
> 1. **EMA codebook update**：SoundStream/Encodec 采用。
> 
> 1. **Codebook 重初始化**：检测不用的 code 以 batch 中随机 sample。
> 
> 1. **分量重要采样 (RVQ)**：多层 codebook 逆差分解。
> 
> 1. **Gumbel softmax**：软分配，梯度可传。
> 
> **所有这些都增加了调参复杂度。**

---

## 3.1.3.5 FSQ 为何免疫

> [!important]
> 
> FSQ「codebook」**隐式为完整的等间隔网格**：
> 
> 1. **所有 code 同时存在**，不需「启动」。
> 
> 1. **encoder 输出不同** $z$ **自然映射到不同量化点**，会肤表现为 $p_k \sim$ 均匀。
> 
> 1. **仅依赖 encoder 的表达多样性**，不依赖量化器。
> 
> FSQ 作者报告：同代码 base 下使用率 90%+ vs VQ 使用率 ~30%。

## 3.1.3.6 实验验证

```python
import torch

with torch.no_grad():
    z = encoder(audio)                            # (B, T, D)
    codes = fsq_to_codes(z)                       # (B, T, d_groups)
    flat = codes.reshape(-1, codes.size(-1))
    code_ids = flat.unique(dim=0)
    print(f"unique codes: {code_ids.size(0)} / {K}")
    p = torch.bincount(
        flat[:, 0], minlength=L
    ).float() / flat.size(0)
    perplexity = torch.exp(-(p * (p + 1e-10).log()).sum())
    print(f"perplexity dim 0: {perplexity:.1f}")
```

## 3.1.3.7 踩坑记录

> [!important]
> 
> **坑 1：以 VQ 思维诊断 FSQ collapse** → FSQ 使用率始终 100%（所有点都可达），需看**概率平均性**而不是使用率。
> 
> **坑 2：encoder 输出饱和 (tanh 后接近 ±1)** → 仅边界点被使用，需 norm 控制范围。
> 
> **坑 3：多组 FSQ 中** $L$ **选偏不均匀** → 某些维度被过度使用。推荐 $L$ 各组上一致。
