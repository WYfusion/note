> [📎] 前置知识：累计分布函数（CDF）、Nucleus Sampling、采样概率质量、Tail 压制。

> **定位**：拆解 Top-p（Nucleus Sampling）——公式、实现、与 Top-k 联用的动态裁剪逻辑、为什么 GPT-SoVITS 默认 0.8 而非 GPT 默认 0.95。

## 1. 公式

设按概率降序排列后 $p_{(1)} ge p_{(2)} ge cdots ge p_{(V)}$。找最小 $K$ 使：

$$\sum_{i=1}^{K} p_{(i)} \ge p_{\text{thr}}$$

保留前 $K$ 个，其余设为 $-\infty$ 重归一化后采样。

## 2. PyTorch 实现

```python
def top_p_logits(logits, p):
    sorted_logits, sorted_idx = torch.sort(logits, descending=True)
    cum = torch.cumsum(F.softmax(sorted_logits, dim=-1), dim=-1)
    # 创建 mask：累计 > p 的要 mask
    mask = cum > p
    # 向右移位，保留刚超过阈值的那一个
    mask[..., 1:] = mask[..., :-1].clone()
    mask[..., 0] = False
    sorted_logits[mask] = float('-inf')
    # 恢复原顺序
    out = sorted_logits.gather(-1, sorted_idx.argsort(-1))
    return out
```

## 3. Top-p 与 Top-k 的联动

GPT-SoVITS 顺序：

```jsx
原始 logits → rep_pen → / T → top_k(15) → top_p(0.8) → sample
```

Top-k=15 **硬别上限**，在这 15 个中再 top_p=0.8 动态裁剪。两种极端场景：

|场景|top_k 后分布|top_p 后保留|
|---|---|---|
|高置信（p_1=0.9）|0.9, 0.05, 0.02, ...|**仅 1 个**（几乎贪心）|
|不确定（平均分布）|0.08, 0.07, 0.07, ...|**保留8–11 个**|

> [💡] **联动价值**：Top-p 在不确定场景保持多样性，在高置信场景退化为贪心——「自适应随机度」。这是原论文（Holtzman 2020）的核心主张。

## 4. GPT-SoVITS 默认 0.8 vs GPT-2 默认 0.95

|系统|top_p|为什么|
|---|---|---|
|GPT-2 文本|0.95|文本要多样性，允许 5% 尾巴|
|**GPT-SoVITS**|**0.8**|TTS 对 OOD token 鲁棒性差，压尾|
|VALL-E|1.0|论文不裁剪|
|CosyVoice 2|0.8|同 GPT-SoVITS|

> [⚠️] **上调 top_p 的代价**：p=0.95 会允许低概率尾巴 token 被采中——semantic codebook 的尾巴常是「吃坏」类型误入 token，一旦被采上 → 听感。推荐范围：0.7–0.85。

## 5. Top-p 的 corner case

```python
# p 近于 0 时
if p == 0: 
    # 等价于 top_k=1 (greedy)
    return greedy_decode(logits)

# p = 1 时
if p >= 1.0:
    # 等价于不裁剪
    return logits
```

实现中要避免「全部 → -inf」崩溃：mask 右移一位保留「刚超过阈值的那一个」，保证至少 1 个 token 可采。

## 6. 工程判断

> [🔧] **调参扫描顺序**：①先调 `top_k` 定距；② 再调 `temperature`；③最后微调 `top_p`。`top_p` 是「精调旋钮」，动 0.05 听感差别明显；明显大于这个粒度调参应课其他参数。
