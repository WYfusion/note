## 1. 训练目标公式

记输入条件 $c = (text{phoneme}, text{bert}, text{ref_sem})$，目标序列 $s = (s_1, dots, s_T, text{EOS})$，词表大小 $V_{text{sem}} = 1024$，加上 EOS 共 $1025$。损失为标准 AR 交叉熵：

$$\mathcal L_{\text{AR}} = -\frac{1}{T+1} \sum_{t=1}^{T+1} \log p_\theta(s_t \mid s_{<t}, c)$$

实现上是 `F.cross_entropy(logits.transpose(1,2), targets, ignore_index=-100)`。Teacher forcing：训练时输入 $s_{<t}$ 用 ground-truth，不用模型预测。

## 2. `ignore_index` 的两个作用

PyTorch `F.cross_entropy(ignore_index=-100)` 会 **跳过** 值为 `-100` 的位置。GPT-SoVITS 用它来：

1. **屏蔽 phoneme / reference 段的预测**：模型虽然在这段上也输出 logits，但我们 **不希望** 它学着「重建参考语义」，只想让它学「基于条件预测目标」。把这两段的 target 设为 `-100`。

1. **屏蔽 padding**：batch 内序列长度不齐，padding 位也置 `-100`。

> [⚠️] **常见踩坑**：自己实现时把 phoneme 段也算进 loss → 训练后模型会「复读机」式重复参考音频前几个 token，CER 飙升。

## 3. EOS Token 与 `early_stop_num`

- **训练**：每条目标序列末尾追加 EOS，目标长度 = $T+1$，模型学会「在合适位置预测 EOS」。

- **推理**：每步检查 `argmax == EOS` 或采样到 EOS；若是，立即停止。另设上限 `early_stop_num=1600`，防止模型卡死无限生成（在 25Hz 下对应 64s 音频）。

> [💡] **为什么 64s 上限？** ①训练数据 95% 切片在 20s 内，60s 已是长尾极限，超出后注意力质量崩塌；②inference UI 单段 sentence 几乎不会超 30s；③1600 也契合 v1 上下文 1024 + 文本约 100 + 参考约 250 = 总长 ≤ 2048 的预算。

## 4. Dataset 封装（`AR/data/dataset.py`）

每条样本一个三元组 `(phoneme, ref_sem, tgt_sem)`：

```python
class Text2SemanticDataset(Dataset):
    def __getitem__(self, idx):
        ph_ids   = self.cleaned_phonemes[idx]    # [T_p]
        bert     = torch.load(self.bert_paths[idx])  # [T_p, 1024]
        ref_sem  = self.ref_semantics[idx]        # [T_r]
        tgt_sem  = self.tgt_semantics[idx]        # [T_t]
        return ph_ids, bert, ref_sem, tgt_sem
```

`collate_fn` 负责：

1. 把同 batch 序列 pad 到最长；

1. 构造拼接后的 input / target 张量；

1. 对 phoneme / ref 段 target 置 `-100`；

1. 返回 `(input_ids, target_ids, attn_mask)`。

## 5. 训练目标的工程判断

|设计|选择|理由|
|---|---|---|
|损失|CE on semantic token only|semantic 是离散，自然用 CE；声学交给 SoVITS|
|ignore_index|-100|屏蔽条件段 & padding，避免训坏|
|Label smoothing|❌ 不用|词表小（1025），过度平滑会让 logits 趋平、推理失真|
|Length normalization|❌ 不用|AR 自然处理变长|
|Auxiliary loss|❌ 不用|单流单目标，越简单越稳|

> [🔧] **训练监控信号**：①每 epoch 末看 val loss 是否稳降；②CE 收敛参考值 ~2.5–3.0（v1）；③推理 dev set 上 EOS 命中率应 > 95%，否则 early stop 兜底会触发 64s 噪声尾巴。
