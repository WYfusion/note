> [📎] 前置知识：Cross-Entropy Loss、`F.cross_entropy`、`ignore_index`、Padding Mask、多类分类、Teacher Forcing。

> **定位**：拆解 GPT-SoVITS AR 训练时 loss 是怎么算的、「不该算的位置」怎么被屏蔽、`ignore_index=-100` 为什么是这个黑魔法数字、是否要 label smoothing。

## 1. 公式与实现

训练目标：

$$\mathcal L_{\text{AR}} = -\frac{1}{N} \sum_{t \in \mathcal T_{\text{valid}}} \log p_\theta(s_t \mid s_{<t}, c)$$

其中 $\mathcal T_{\text{valid}}$ 是「需要计入 loss 的位置集合」（只含 tgt 段）。

实现（`AR/models/t2s_model.py`）：

```python
logits = self.ar_predict_layer(hidden)          # [B, T, V+1]
loss = F.cross_entropy(
    logits.transpose(1, 2),                       # [B, V+1, T]
    targets,                                       # [B, T]
    ignore_index=-100,
)
```

## 2. `ignore_index=-100` 深入

PyTorch `F.cross_entropy` 有个参数 `ignore_index`，该位置的 target 不会贡献 loss、也不贡献梯度。默认 `-100` 是 PyTorch 的约定俗成、与 label 不会冲突（vocab id 都是非负）。

### 作用 1：屏蔽 phoneme / ref 段

```python
# collate_fn中构造 target
target = full_input.clone()                  # 全序列
target[:, :T_p + T_r] = -100                 # phoneme + ref 段不计 loss
target[:, :-1] = full_input[:, 1:]            # shift left 一位（下一 token 预测）
target[:, -1]  = -100                         # 最后一位无计算
```

> [⚠️] **常见踩坑**：如果 phoneme 段也算 loss，模型会「复读机式」重复参考音频前几个 token——CER 骤升、生成出「嘴巴」鬼画符语音。这是复现训练时最常见的错误。

### 作用 2：padding 位置

batch 内序列变长，低于最长的都需 pad。pad 位置 target 也设 `-100`：

```python
for i in range(B):
    target[i, lens[i]:] = -100
```

### 作用 3：EOS 后的位置

EOS 本身要计 loss（让模型学到「在哪里停」），EOS 后的 pad 设 `-100`。

## 3. 为什么不用 label smoothing

标准词表平滑：

$$q_i = (1 - \epsilon) \mathbf 1[i = y] + \frac{\epsilon}{V}$$

GPT-SoVITS 取 $\epsilon = 0$，原因：

1. **词表小**（1025），过度平滑会让每个错误类都被助推，logits 趋平，采样时多样性起但准确性跳水；

1. **语义 token 本身是离散化后的「硬类别」**，不是人类语言词（同义词可互换），平滑在语义上不成立；

1. 社区实验表明加 0.1 smoothing 后 CER 上升 ~0.3%、音质不变。

> [🤔] **与机翻、文本生成的差异**：机翻 / 文本生成用 smoothing 是防过拟合 + 鼓励多样性，TTS 语义 codebook 魎透不同，不适用。

## 5. 工程判断

> [🔧] **调试 checklist**：①在 collate 处插 `assert (target != -100).sum() > 0`防止全 mask；②打印首 batch 的 `target[0]` 检查 `-100` 位置是否同 phoneme+ref 范围一致；③检查 `logits.shape == [B, V+1, T]`，少一个轴 dropout 会让 cross_entropy 报错。
