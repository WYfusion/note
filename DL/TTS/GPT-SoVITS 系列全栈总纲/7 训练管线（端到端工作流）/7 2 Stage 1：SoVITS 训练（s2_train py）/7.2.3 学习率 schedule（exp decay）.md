> [📎] 前置知识：ExpDecay、Warmup、Cosine、AdamW 超参、G/D 不同步。

> **定位**：s2_[train.py](http://train.py) 使用 ExponentialLR 调度器，本节拆其补充试、 不同架构 (GAN vs CFM) 的调度区别、与 AR (Warmup+Cosine) 的区别。

## 1. 公式

$$lr_t = lr_0 \cdot \gamma^t$$

- $lr_0 = 10^{-4}$

- $\gamma = 0.999875$

- t ∈ epoch index (不是 step!)

```python
# GPT_SoVITS/s2_train.py
scheduler_g = torch.optim.lr_scheduler.ExponentialLR(
    optim_g, gamma=hps.train.lr_decay, last_epoch=epoch_str - 2)
scheduler_d = torch.optim.lr_scheduler.ExponentialLR(
    optim_d, gamma=hps.train.lr_decay, last_epoch=epoch_str - 2)
```

## 2. 衰减率可视化

|epoch|lr|衰减 %|
|---|---|---|
|0|1.0e-4|baseline|
|100|9.876e-5|-1.2%|
|500|9.394e-5|-6.1%|
|2000|7.787e-5|-22.1%|
|5000|5.351e-5|-46.5%|
|10000|2.864e-5|-71.4%|

> [💡] **衰减极缓**：每 epoch 仅衰 0.0125%，十年才反出明显。这是 VITS 原设计。原因是 GAN 训练 不能「猛降」，衰减太快会让 D 压过 G。

## 3. G 与 D 同步 lr

原 VITS 选 G 与 D 同一 lr。GPT-SoVITS 同。例外：

> [💡] **难调点**：社区发现「如果 D 越当、代 model collapse」。但 GPT-SoVITS default 什么都不动，选戋丝不动。原因是 mel × 45 loss 主导、GAN 仅为「加锐」，难调 问题不多。

## 4. v3/v4 CFM 也用 ExpDecay

CFM 训练中，s2_[train.py](http://train.py) 仍 用同一调度器 (仅 G、无 D)：

```python
# v3/v4 CFM 路线
scheduler_g = ExponentialLR(optim_g, gamma=hps.train.lr_decay)
# 无 scheduler_d
```

不需 warmup 是因 CFM L2 loss 比 GAN 如烍， 一开始 high lr 不会炸友。

## 5. 与 AR 的 LR 调度差异

|项|SoVITS (s2)|AR (s1)|
|---|---|---|
|schedule|**ExpDecay**|**Warmup + Cosine**|
|warmup steps|0|1000|
|peak lr|1e-4|1e-4|
|衰减周期|epoch|step|
|原设计|VITS 原报|GPT-2 风格|

> [🤔] **为何两阶段不同**：SoVITS 是「帧级任务」、GAN 主导，需稳定 low-lr；AR 是「token 预测」、CE loss，需 warmup 防炸友、cosine 加起 final 红炸。两者调度器不同是任务本质决定的。

## 6. 加载 resume 时的处理

```python
scheduler_g = ExponentialLR(
    optim_g, gamma=hps.train.lr_decay,
    last_epoch=epoch_str - 2)        # ← 重点
```

`last_epoch=epoch_str - 2` 是为了 resume 时从正确的 lr 偏离点重起。 -2 是因 epoch_str 是「下一个 epoch 号」、 -1 会才能「衰 1 次」。

## 7. 工程判断

> [🔧] **不要动 lr_decay**：VITS 选 0.999875 是多年调过的点。 社区报错主要是「AR loss 不降」、「生成坏」——不是 lr 问题。 调参优先能 去看 loss、ckpt、重跳 ckpt 能否生成。
