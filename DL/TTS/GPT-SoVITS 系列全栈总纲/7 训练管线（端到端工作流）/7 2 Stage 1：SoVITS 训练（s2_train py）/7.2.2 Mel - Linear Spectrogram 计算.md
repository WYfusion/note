## 2. Linear Spectrogram

```python
# GPT_SoVITS/module/mel_processing.py
def spectrogram_torch(y, n_fft, sampling_rate, hop_size, win_size, center=False):
    hann_window = torch.hann_window(win_size).to(y.device)
    y = F.pad(y.unsqueeze(1),
              (int((n_fft - hop_size) / 2),
               int((n_fft - hop_size) / 2)),
              mode='reflect').squeeze(1)
    spec = torch.stft(y, n_fft, hop_length=hop_size,
                      win_length=win_size, window=hann_window,
                      center=center, pad_mode='reflect',
                      normalized=False, onesided=True, return_complex=False)
    spec = torch.sqrt(spec.pow(2).sum(-1) + 1e-6)   # 振幅
    return spec    # [B, n_fft/2 + 1, T]
```

- bins 数：$text{FFT}/2 + 1$

- v2 default：FFT=2048 → 1025 bins

- v4 (48k)：FFT=2048 → 1025 bins

## 3. Mel Spectrogram

```python
# 同一脚本
def mel_spectrogram_torch(y, n_fft, num_mels, sampling_rate,
                          hop_size, win_size, fmin, fmax, center=False):
    mel = mel_basis(num_mels, n_fft, sampling_rate, fmin, fmax)  # cached
    spec = spectrogram_torch(y, n_fft, sampling_rate, hop_size, win_size, center)
    mel_spec = torch.matmul(mel, spec)               # [B, n_mels, T]
    mel_spec = torch.log(torch.clamp(mel_spec, min=1e-5))
    return mel_spec
```

使用 librosa-Slaney 标准 mel filterbank（带 norm='slaney'）、不是 HTK。

## 4. 参数表

|参数|v1/v2 (32k)|v3 (24k)|v4 (48k)|
|---|---|---|---|
|n_fft|2048|1024|2048|
|hop_size|**480**|256|512|
|win_size|2048|1024|2048|
|n_mels|**128**|100|100|

|fmax|None (半采样率)|12000|**24000**|
|帧率|66.67 Hz|93.75 Hz|93.75 Hz|

> [💡] **v3/v4 mel 帧率一致**：93.75 Hz。这是 BigVGAN-24k-256x 与 BigVGAN-48k-512x 都默认设计的。二者仅最后上采样 256× vs 512× 不同。

## 5. hop / win / fft 三者关系

```jsx
hop_size  : 相邻帧中心间隔 (帧率 = sr / hop)
win_size  : Hann 窗长度 (谱频分辨率 ≈ sr / win)
n_fft     : FFT 点数 (频谱 bin 数 = n_fft/2 + 1)
```

三者必须满足：$text{win} le n_text{fft}$、$text{hop} le text{win}/4$ （重叠 75%）。

## 6. center=False 重要性

```python
torch.stft(..., center=False, ...)
```

`center=True`（PyTorch default）会在序列两端填补 win_size/2，使输出帧数 ≈ T/hop + 1。 GPT-SoVITS 选 `center=False` 使帧数 严格为 $lfloor (T - text{win}) / text{hop} rfloor + 1$，与其他特征对齐。

> [⚠️] **center 不一致 会造成 mel 与 SSL 越准**：预处理 与 训练 不同样的 center 设置会产生帧数不同，训练时 loss 越准决。

## 7. Posterior 与 Loss 用途拆分

|频谱类型|用途|原因|
|---|---|---|
|Linear Spec|**Posterior Encoder 输入**|不损信息, q(z\|x) 需完整频谱|
|Mel Spec|**重构 loss target**|感知 加权、人耳不坏|

> [💡] **Linear 输入、Mel 监督是 VITS 原设计**。Posterior 看完整谱的 q(z|x) 能压缩到 z，后面 Decoder 能在听感加权上优化。

## 8. 工程判断

> [🔧] **mel_basis 要缓存**：每个 forward 重新 librosa.filters.mel 是极贵的（太 CPU 创建 · 传 GPU · 丢弃）。社区 代码 以 functools.lru_cache + 额外 dict cache mel 矩阵。
